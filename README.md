# Parallax Hedge — Arcus × RHC Lighter 对冲刷量控制台

在 **Arcus** 和 **Robinhood Chain 上的 Lighter** 之间开一对方向相反、数量相同的永续仓位（一边多、一边空），
用尽量少的磨损刷交易量。这不是靠它赚钱的策略。

带可视化网页面板、一键启动、演练模式、多币种并行、风控三道防线、孤腿抢救、成交账本对账。

> ⚠ **风险提示**：数字资产衍生品交易可能损失全部本金。本项目按「原样」提供（MIT 许可），
> 不构成投资建议，作者不对任何使用后果负责。请先用演练模式、再用小额实盘验证。
>
> 默认 `DRY_RUN=true`：照常做全部判断并记录意图，但**不会下任何单**。

## 快速开始（Windows）

1. 下载 / 解压本项目到任意目录（路径里最好不要有中文和空格）。
2. 双击 **`一键启动.bat`**。第一次运行会自动完成：
   - 找本机的 Python 3.11 / 3.12；**没有就自动下载并为当前用户安装 Python 3.11**（不需要管理员权限）；
   - 在项目目录里建独立的虚拟环境 `.venv`，安装依赖（官方源失败会自动改用清华镜像）；
   - 从 `.env.example` 生成 `.env`（演练模式）。
   首次大约需要几分钟，之后每次启动只要几秒。
3. 浏览器自动打开 `http://127.0.0.1:8004/`。关掉黑色窗口 = 停止程序。

macOS / Linux：`./start.sh`（需要自行安装 Python 3.11 或 3.12）。

## 配置密钥

仓库里的 `.env` 是空模板。把你自己的地址和密钥抄进去，或在面板「账户设置」里填。不要把真密钥写进文档或提交。

用记事本打开项目目录里的 `.env`，填这几项。用记事本改完 `.env` 要重启。在「账户设置」里保存则按页面提示，不用重启。密钥那一栏留空再保存，会保留原来的密钥，不会清成空白。保存之后密钥显示 `****`，地址只显示头尾几个字符。子账户和索引仍显示完整数字。

面板四个页：**资金费总览**、**轮换任务**、**系统**、**账户设置**。账户页填地址、子账户、索引和密钥。

| 键 | 说明 |
| --- | --- |
| `ARCUS_ADDRESS` | Arcus 主钱包的**公开地址**（0x + 40 位） |
| `ARCUS_ACCOUNT_INDEX` | 子账户编号 0~9 |
| `ARCUS_API_PRIVATE_KEY` | Arcus 的 Ed25519 **API 私钥**（网页 API Keys 页生成时显示的 API Signing Key，只显示一次；**最长 180 天有效，到期要重新生成**）；也可以用 `ARCUS_API_PRIVATE_KEY_FILE` 指向一个文件 |
| `ARCUS_API_KEY` | 可留空（程序由私钥推导）；填了就必须和私钥是一对 |
| `LIGHTER_ACCOUNT_INDEX` | Lighter 账户编号 |
| `LIGHTER_API_KEY_INDEX` / `LIGHTER_API_PRIVATE_KEY` | Lighter 的 API key 编号（4～254，0～3 和 157 是官方保留的）和对应私钥 |
| `ARCUS_PROXY` / `LIGHTER_PROXY` / `GLOBAL_PROXY` | 每个所可配独立代理，留空走共用，再空直连；支持 `http://`、`socks5://user:pass@host:port`、`host:port:user:pass` |

**只填 API 私钥，永远不要填钱包助记词或钱包私钥。** `.env` 已在 `.gitignore` 里，不要把它上传到任何地方。

没填密钥时面板照样能打开，可以看两所共有币种和资金费率。

## 切实盘之前

1. 在「轮换任务」页建任务，先在演练模式下看几轮决策是否合理。
2. 点 **「实盘预检」**，全部通过（不下任何单，只验签名、时钟、余额、精度，并把 Arcus 的单**真签一遍但不发**）。
3. 把 `.env` 里 `DRY_RUN` 改成 `false`，重启。第一次建议「单边名义上限」填 20~30 USDC。
4. 第一笔真实开仓后，在 Arcus 网页上看一眼仓位，和面板「持仓与强平距离」对一下（见下文「强平价」）。

## 它怎么工作

目的是对冲刷量、尽量不亏，不是买低卖高。两所之间本来就有价差，Arcus 空 80000、Lighter 多 80001 这样也可以开。不要求买在更便宜的一边。两个所重叠的市场都走这套规则，包括美股永续。

开仓时两边一起挂 maker（Arcus 0 费，Lighter 0 费）。一边成交不把另一边改成 IOC，也不把已成交的一边改成吃单。计划内平仓两边都挂 maker。只有风控和临近强平才吃单。关掉程序时撤掉挂单，并把还开着的仓位挂 maker 平掉。

扫描间隔在面板上（默认 20 秒，最短 5 秒）。最短持有、最长持有、浮盈亏差额也在面板上，改完下一轮就用，不用重启。不再用价差多少 bp 决定开仓或平仓，下单设置里也没有这个字段。

- **开仓**：不看谁贵。所间价差不拦，也不拿「浮盈亏差额」拦。两边一起挂 maker。`POST_ONLY_WOULD_CROSS` 就往不吃单的一侧挪一档再挂，不放弃另一条腿。只成交了一边时，未成交的 maker 留着，已成交的一边另挂 post-only 退出（跟买一/卖一）。不撤未成交的对冲单，也不吃单。两边都还没成交、盘口挪了，就一起跟新的买一/卖一。
- **平仓**：两条腿都成交之后，至少再持有面板上的最短时间（默认 3 秒）。然后只看每一边自己的开仓价对上自己的 maker 平仓价，两腿加总。不低于「负的浮盈亏差额」（面板那一个字段，默认 0.02 USDC，可改成 0.05 或 0.01）就挂 maker 平。两边书没动，合计接近 0，要平。所间价差不算进这笔亏损。合计正好等于负的差额，也平；更差就继续挂着等。持有满最长持有（默认 300 秒）可以跟盘挂 maker 平；这些挂单价仍然亏过差额时就继续挂着，不因为到点改吃单。

计划内平仓在发单前用每一边自己的开仓价对上即将挂出的平仓价重算，不能只看标记浮盈亏，也不把两所价差算成亏损。按这个合计差于面板「浮盈亏差额」时，先不发单，继续挂着。到了最长持有可以跟盘挂 maker，但仍然不吃单。正常平仓两边都挂 maker，一边成交后不把另一边改成吃单。过不了差额就撤掉未成交的 maker，剩下的仓继续挂 maker。风控和临近强平仍立刻吃单。孤腿不是这条吃单路径：只挂 maker 退出。
- **仓位大小**：按两边可用保证金里小的那一边算，再按任务的「单边名义上限」截断。

下面这些旧说法作废：按资金费选方向、持有固定周期再平、两条腿隔 3 秒、只让一边挂单另一边吃单。

### 风控（安全动作永远压过交易动作）

1. **开仓前预检**：估算的强平距离低于 `MIN_CORRIDOR_PCT`（默认 3%）就不开；两所中价相差 3% 以上不开（防止同名不同物）；低于最小下单额不开。
2. **开仓后复核**：用真实仓位重算强平距离，比预期差就立刻两边一起平。
3. **持仓监控**：任一条腿离强平小于 `CLOSE_CORRIDOR_PCT`（默认 1.5%），或剩余距离掉到开仓时的一半，**两边同时平掉，绝不单腿止损**。
4. **孤腿**：任何时候只剩一条腿，挂 post-only 退出，跟买一或卖一。会吃单就挪一档再挂，不市价、不 IOC。开仓时只成交了一边也一样，未成交的那条继续挂着。
5. 下单请求超时**不重发、也不当成没下**，按仓位判断成没成交；开仓前先把 Arcus 的单签好，签不出来就不碰 Lighter。

### 强平价

Arcus 不返回强平价，程序按账户权益和维持保证金率自己算，并按**最坏情况**把账户里其它 Arcus 仓位也算成同向一起亏。
所以面板上的强平价通常比 Arcus 网页上显示的**更近**：Arcus 网页假设只有这一个币在动，程序假设账户里所有仓位一起动
（全仓下这才是整个账户真正会被强平的位置）。

## 全部设置（`.env`）

除了上面的密钥，其它都有默认值，一般不用改：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `PORT` | 8004 | 面板端口 |
| `DRY_RUN` | true | `true` 演练 / `false` 实盘 |
| `ENGINE_CYCLE_SECONDS` | 20 | 引擎多久跑一轮 |
| `MIN_CORRIDOR_PCT` | 3 | 开仓门槛：估算离强平不足这么多就不开 |
| `CLOSE_CORRIDOR_PCT` | 1.5 | 平仓线：离强平小于它就两边一起平 |
| `REOPEN_COOLDOWN_SECONDS` | 60 | 平仓后隔多久才允许重开 |
| `ORDER_SLIPPAGE_BPS` | 10 | 紧急处理时的滑点上限。正常开平走 maker |
| `ARCUS_MAKER` | true | 两边一起挂 maker。一边成交不把另一边或已成交的一边改成吃单 |
| `MAKER_WAIT_SECONDS` | 120 | 挂单最多等多久。两腿都没成交才撤。只成交一边就另挂 post-only 退出，不撤另一条 |
| `MIN_HOLD_SEC` | 3 | 两腿都成交后至少持有这么多秒，才按浮盈亏平仓。面板上也能改 |
| `MAX_HOLD_SEC` | 300 | 持有满这么多秒可以跟盘挂 maker 平。亏过差额也不改吃单 |
| `PNL_CLOSE_USD` | 0.02 | 浮盈亏差额（USDC）。只用于每一边自己的开仓价对上自己的平仓价。所间价差不拿它拦开仓 |

程序升级后新增的设置项会自动补进 `.env`（只追加，不改已有的行）。

## 注意事项

- **同一个 Lighter 账户上还有别的程序在跑时**：不能共用同一个 `LIGHTER_API_KEY_INDEX`（nonce 会互相顶掉），
  也不要让两个程序交易同一个币种（会把对方的腿当成孤腿平掉）。
- Arcus 拒收时间偏差 30 秒以上的签名请求，请保持系统时间同步。
- Arcus 的美股等品种有交易时段，休市时杠杆上限会降低、盘口会变薄，挂单成交会明显变慢。
- 所有状态存在项目目录的 `data/`（SQLite）；删掉它等于清空任务和账本。

## 开发

```bash
python -m venv .venv && .venv/bin/pip install -e ".[dev]"   # Windows: .venv\Scripts\pip
python -m pytest
```

`tests/` 下 358 个用例，覆盖 Arcus 签名（与 JS 实现逐字节对拍）、回执解析、强平价复算、超时不重发、
基差闸门、挂单与即时对冲、补仓、成交对账等。

代码结构（`src/parallax_hedge/`）：

| 文件 | 作用 |
| --- | --- |
| `engine.py` | 引擎：每轮串起快照、风控、预检、调度、执行 |
| `risk.py` / `scheduler.py` | 风控与调度决策（纯函数，不碰网络） |
| `execution.py` / `maker.py` | 吃单 / 挂单执行 |
| `arcus.py` / `arcus_ws.py` | Arcus 签名、精度、强平价；订单推送 |
| `exchanges.py` | 两所 REST 客户端 |
| `ledger.py` / `store.py` | 成交账本与对账、SQLite 存储 |
| `api.py` / `web/` | 面板后端与前端 |
